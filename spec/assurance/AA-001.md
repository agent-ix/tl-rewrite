# tl-rewrite v0.1 source-release argument

## Claim

The open claim concerns only the exact source, catalog, dependencies, corpora,
and evidence presented to the human owner. It excludes downstream qualification
and registry publication.

## Reasoning

Complete provenance, deterministic budget, replay, and bounded comparison
obligations reduce uncertainty for the stated use. Human review owns sufficiency.

## Sufficiency Decision

The claim remains open until retained evidence names the exact candidate, every
enabled rule has current evidence, blocking gaps close, and the human owner
records a decision. Automation cannot change this status.

## Challenges

Bounded enumeration and WEST fixtures are not a universal proof of arbitrary
rewrites and cannot qualify a production monitor or consuming project.

The exact `tl-syntax` git-source exception remains open. `tl-syntax` PR #10 has
merged as `953ee825`, but this repository cannot adopt that revision while
`tl-mltl` still pins `740182f1`; see **Upstream Pin** below for the measured
reason. `tl-mltl` is pinned to its merged `main` revision. The source-release
claim stays blocked until the pin can move.

Qualification is no longer host-scoped, because the machinery that made it so
is gone. `tools.lock`, the host-identity gate, the evidence collector, the
finalizer, the manifest verifier, the anchor gate and the retraction registry
were removed by the migration under issue #9. Retention, integrity checking,
audit, attestation, change records and receipts are now owned by Quoin; static
specification and coverage facts by Quire; the compatibility matrix and the
PGM-01 mapping by Engineering Assurance. `make ci` is the single local gate and
is portable.

## Retained Archive

The eleven records under `evidence/` are immutable and every retained byte is
unchanged. There is no local verifier for them and no anchor file with an
enforcing reader; Git history and pull-request review are the integrity
boundary, which is what `CONTRIBUTING.md` has always said, and
`scripts/legacy_evidence_view.py` asks Git directly rather than maintaining a
second local manifest.

Read through the pinned Engineering Assurance mapping, all eleven envelopes are
`quire.derivation-evidence/v1` and every one of them classifies as
`incompatible` with the reason *"unknown PGM-01 schema version"*. That is the
mapping declining to interpret a shape it has never seen. It is reported as it
stands and is not converted into a pass. Filed upstream as
`agent-ix/engineering-assurance#21`.

## Make Is Not a Trust Root

This argument previously leaned, in part, on a parse-time guard that inspected
the `Makefile`'s own execution controls. That guard was removed with the
collector it protected, and the correction is recorded here rather than left
implicit.

Measured at the migration revision on this repository's own Makefile, not inherited from a sibling. With every tool variable pointed at `false` so no gate's work happens, `make ci` exits **2** and stops at the first prerequisite. Prepending a single `.IGNORE:` line to the same Makefile makes the identical run exit **0** after 27 ignored recipe failures, and all 13 `ci` prerequisites report success. Twelve of them do so with their own command having failed; the thirteenth, `audit-unsafe`, invokes `bash` directly and is not reachable by the tool-variable sabotage, and a skeleton in which every recipe is replaced by `false` confirms it reports success too, so the count is 13 of 13.

What replaces the guard is structural and covers only part of the gate set.
Quoin binds each retained input by digest and every attested result is derived
from the producer's own bytes, so a producer that did not run yields an absent
or empty input the chain names. That protects the work re-run inside
`make assurance-inputs`. It does **not** protect `fmt-check`, `lint`, `test`,
`check-corpus`, `deny`, `audit-unsafe`, `rustdoc`, or the `quire validate` half
of `spec`, each of which can be neutered while every remaining check stays
green. This is a genuine reduction in local detection. It is tracked as
`agent-ix/tl-rewrite#11` and recorded as an open unknown in
`assurance/change-assurance.json`.

## Upstream Pin

`tl-syntax` merged its own migration as `953ee825` and `tl-parse` repinned to
it. This repository cannot follow yet. Its bounded comparison hands
`tl_syntax::Formula` values directly to `tl_mltl::evaluate_closed`, so both
crates must resolve the same `tl-syntax` revision, and `tl-mltl` at its merged
`main` `fe1c620d` still pins `740182f1`. Repinning only this crate puts two
`tl-syntax` versions in the dependency graph and the build fails with E0308 at
four call sites in `src/equivalence.rs`. That was measured, not predicted. The
pin therefore stays at `740182f1` and the source-release claim remains blocked
on it, exactly as the challenge above states. Tracked as
`agent-ix/tl-rewrite#10`.

## Human Decision

The claim remains open. No `ix-flow` decision event exists for this change; only
the repository owner `@kreneskyp` may create one, and none was synthesized, so
the verification receipt reads `incomplete` with a missing decision rather than
complete. Automation cannot change that.
