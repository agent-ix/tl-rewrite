# tl-rewrite v0.1 source-release argument

## Claim

The open claim concerns only the exact source, catalog, dependencies, corpora,
and evidence presented to the human owner. It excludes downstream qualification
and registry publication.

## Reasoning

Complete provenance, deterministic budget, replay, and bounded comparison
obligations reduce uncertainty for the stated use. Human review owns sufficiency.

## Sufficiency Decision

The claim remains open until the sealed change-assurance record names the exact
candidate revision, every enabled rule has current evidence, blocking gaps
close, and the human owner records a decision. Automation cannot change this
status.

This read "until retained evidence names the exact candidate" before issue #13.
Left as written it would have been an unsatisfiable release gate eleven lines
below a section that disclaims any retained evidence. The condition is restated
against the thing that actually names the candidate — `make assurance` seals a
record bound to `--candidate-revision` on every run — rather than being deleted
or left pointing at an archive that no longer exists.

## Challenges

Bounded enumeration and WEST fixtures are not a universal proof of arbitrary
rewrites and cannot qualify a production monitor or consuming project.

Both git-source exceptions now name merged `main` revisions rather than
revisions on open pull requests, so neither blocks the source-release claim. See
**Upstream Pin** below for why the two had to move together and what was
measured when only one of them did.

Qualification is no longer host-scoped, because the machinery that made it so
is gone. `tools.lock`, the host-identity gate, the evidence collector, the
finalizer, the manifest verifier, the anchor gate and the retraction registry
were removed by the migration under issue #9. Retention, integrity checking,
audit, attestation, change records and receipts are now owned by Quoin; static
specification and coverage facts by Quire; the compatibility matrix and the
PGM-01 mapping by Engineering Assurance. `make ci` is the single local gate and
is portable.

## No Retained Archive

This argument previously had a **Retained Archive** section arguing from eleven
immutable records under `evidence/`. Those records are deleted, and the section
is removed rather than restated more weakly.

The repository owner released the evidence-preservation constraint for the
pre-stable phase on 2026-09-02; the authority is
`agent-ix/engineering-assurance#7`, section *"Preservation constraint released
for the pre-stable phase"*, and the work is tracked as `agent-ix/tl-rewrite#13`.
The epic's completion criterion and its mandatory control were amended before
the deletion, so no live constraint was violated. The constraint re-applies
unchanged at the move toward stable releases.

**This argument no longer claims that any historical evidence verifies.** No
record was rewritten, backdated, re-sealed or moved; 582 files were deleted.
What was measured before deletion is stated in `assurance/pins.json` and is not
repeated here as though it were current. Git history and pull-request review
remain the integrity boundary, which is what `CONTRIBUTING.md` has always said,
and it is now the only boundary those bytes are under.

## Make Is Not a Trust Root

This argument previously leaned, in part, on a parse-time guard that inspected
the `Makefile`'s own execution controls. That guard was removed with the
collector it protected, and the correction is recorded here rather than left
implicit.

Measured on this repository's own Makefile at the migration revision, not inherited from a sibling, and with the command named so the number can be re-derived. Run `make ci CARGO=false PYTHON=false QUIRE=false QUOIN=false ASSURANCE_DIR=target/ig-probe ASSURANCE_PYTHON=/bin/false` so that no gate's work happens: `make ci` exits **2** and stops at the first prerequisite. Prepend a single `.IGNORE:` line to the same Makefile and run the identical command: it exits **0** after **25** ignored recipe failures, and all 13 `ci` prerequisites report success. Eleven of them do so with their own recipe having failed; `assurance` is an aggregate whose two sub-targets each failed and were ignored; `audit-unsafe` invokes `bash` directly and is not reachable by the tool-variable sabotage, and a skeleton Makefile in which every recipe is replaced by `false` confirms it reports success too.

What replaces the guard is structural and covers only part of the gate set.
Quoin binds each retained input by digest and every attested result is derived
from the producer's own bytes, so a producer that did not run yields an absent
or empty input the chain names. That protects the work re-run inside
`make assurance-inputs`. It does **not** protect `fmt-check`, `lint`, `test`,
`check-corpus`, `deny`, `audit-unsafe`, `rustdoc`, or the `quire validate` half
of `spec`, each of which can be neutered while every remaining check stays
green. This is a genuine reduction in local detection. It is tracked as
`agent-ix/tl-rewrite#11` and recorded as an open unknown in
`assurance/change-assurance.json`.

## Upstream Pin

Both temporal dependencies now resolve to revisions reachable from their own
`main`: `tl-syntax` moves from `740182f1` to `953ee825`, and `tl-mltl` from
`fe1c620d` to `f7eb8bdf`.

The order was forced and is worth recording, because this repository first tried
it the other way round and measured the failure. `src/equivalence.rs` hands
`tl_syntax::Formula` values straight to `tl_mltl::evaluate_closed`, so both
crates must resolve the *same* `tl-syntax` revision. While `tl-mltl` still pinned
`740182f1`, moving only this repository's pin put two `tl-syntax` versions in the
dependency graph and cargo reported E0308 at four call sites with *"there are
multiple different versions of crate `tl_syntax` in the dependency graph"*. The
repin therefore waited for `tl-mltl`'s own migration to merge, which it has.

`deny.toml`'s `allow-git` entries remain, because both dependencies are still git
sources and `unknown-git` is denied. What has changed is the reason: they are no
longer time-boxed exceptions for revisions on open pull requests, but exact pins
on merged `main` revisions of two repositories in the same program. The
source-release claim is no longer blocked on either pin.

The residue is discharged. This repository's eleven retained evidence records
named `tl-mltl` `da2c7704`, a commit reachable from no remote ref and from no
tag, so it existed only on one machine. `agent-ix/tl-mltl` pushed
`origin/retain/tl-mltl-v0.1-da2c7704` to keep it fetchable while those records
stood, and filed `agent-ix/tl-mltl#11`. The records no longer stand: issue #13
deleted all eleven. `tl-mltl`'s own deletion, merged as `58f858e`, had already
removed the eight files on its side that named the revision, so **these eleven
records were the last references to `da2c7704` anywhere in the campaign, and
this change removes them.** Nothing now requires that revision fetchable.

This change does not delete the retention branch and does not close
`agent-ix/tl-mltl#11`; both are handled separately once all eight deletions have
landed. It only removes the last reference. This repository never pinned the
revision for the build.
