# tl-rewrite v0.1 architecture

## System Boundary

The trusted rewrite core consumes validated tl-syntax graphs, an immutable v1
rule catalog, and explicit budgets. Context-aware entry points also consume the
shared tl-syntax signal-catalog document and optional requirement-context
document. It emits a separate formula document and native trace report or an
explicit non-success report. Parsing, contract-IR translation, external proof
engines, production monitoring, and release authority remain outside.

## Views

The catalog view contains immutable metadata and applicability decisions. The
execution view rebuilds graphs bottom-up in stable order with checked budgets,
interning, and cycle detection. The context view validates propositions against
one unchanged shared signal catalog and binds its complete bytes and exact
optional caller context into the request. The evidence view replays reports and
calls the exact tl-mltl evaluator for exhaustive bounded comparison.

## Decisions

Logical work units replace wall-clock time in semantic budgets so repeated runs
remain deterministic. Rules cannot select or translate semantic profiles.
Successful output appears only after a fixed point. Equivalence enumeration is
complete for the reported domain but is not generalized into an unstated proof.
Closed contextual v2 forms extend the existing report families; context-free v1
records are not extended in place and retain their bytes.

## Risks

Rules may grow graphs or interact unexpectedly; node/application/work limits,
stable priority, fixed-point checks, and state fingerprints fail closed.
Dependency/corpus drift is isolated by exact revisions and content digests.
Context substitution is isolated by domain-separated request digests and by
revalidating both input and successful output against the supplied catalog.
