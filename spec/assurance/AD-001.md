# tl-rewrite v0.1 architecture

## System Boundary

The trusted rewrite core consumes validated tl-syntax graphs, an immutable v1
catalog, and explicit budgets. It emits a separate formula document and trace
report or an explicit non-success report. Parsing, external proof engines,
production monitoring, and release authority remain outside.

## Views

The catalog view contains immutable metadata and applicability decisions. The
execution view rebuilds graphs bottom-up in stable order with checked budgets,
interning, and cycle detection. The evidence view replays reports and calls the
exact tl-mltl evaluator for exhaustive bounded comparison.

## Decisions

Logical work units replace wall-clock time in semantic budgets so repeated runs
remain deterministic. Rules cannot select or translate semantic profiles.
Successful output appears only after a fixed point. Equivalence enumeration is
complete for the reported domain but is not generalized into an unstated proof.

## Risks

Rules may grow graphs or interact unexpectedly; node/application/work limits,
stable priority, fixed-point checks, and state fingerprints fail closed.
Dependency/corpus drift is isolated by exact revisions and content digests.
